# 文書の索引検索

文書の索引語から掲載ページを検索する静的Webアプリです。`data` に文書ごとのフォルダとJSONを追加すると、文書の選択肢に自動で加わります。HTML・JavaScript・Pythonの修正や、一覧への登録は不要です。

初期データとして、キタミ式イラストIT塾 応用情報技術者 令和08年版と、令和08年 応用情報技術者 合格教本を収録しています。利用時にサーバー処理・DB・外部サービスへの通信は行いません。

## 公開サイト

[文書の索引検索を開く](https://akanegit.github.io/ap-index-search-kitami-gokaku/)

スマートフォン・PCのブラウザから利用できます。ログインは不要です。

## 使い方

公開サイトを開き、文書を選んで言葉を入力すると部分一致で検索します。英字の大小、全角・半角、空白や一部記号の違いを吸収します。ローカルでは `index.html` のダブルクリックでも利用できます。

検索結果の `p.123` は**本文の掲載ページ**です。「要確認 · 索引 p.940」の番号は、その項目を読み取った**索引ページ**です。`123,125` や `123-125` は索引の表記を残しています。

## 文書の追加

例えば `data/my-manual/entries.json` を作り、UTF-8で保存します。

```json
{
  "entries": [
    { "word": "初期設定", "pages": "12" },
    { "word": "バックアップ", "pages": "30,35-38" }
  ]
}
```

必要なのは `word`（用語）と `pages`（掲載ページ）の2項目です。**どちらも文字列**で、ページ番号も `"12"` のように引用符で囲みます。PDFや画像からの索引抽出は行わないので、用語とページ番号をJSONに用意してください。

- `data` の直下にある1フォルダを1文書として扱います。フォルダ名が文書ID・初期表示名になります。
- フォルダ内のJSONは複数に分けても構いません。`document.json` を除く `*.json` をファイル名順に結合します。サブフォルダ内のJSONは対象外です。
- GitHubの `main` ブランチへ追加すると、自動でデータを生成してサイトを更新します。手元だけで追加した場合は、GitHubへ送信してください。
- `entries` を持つJSONがないフォルダは一覧に表示されません。

### 表示名と順番を指定する場合

同じフォルダに任意で `document.json` を置きます。

```json
{
  "title": "操作マニュアル",
  "order": 30
}
```

`title` は文書の表示名です。`order` は0以上の整数で、小さい文書から表示します。省略時は100、同じ値の場合はフォルダ名順です。

[追加用のひな形](examples/document/) を `data` の下へコピーして、フォルダ名と内容を変更することもできます。

### 任意の索引情報

各項目には次の情報も付けられます。

| 項目 | 内容 | 省略時 |
| --- | --- | --- |
| `needsReview` | 確認が必要なら `true` | `false` |
| `indexPage` | 用語を読み取った索引ページ（0以上の整数） | JSON全体の `indexPage`、それもなければ0（不明） |
| `column` | 索引の列（0=左、1=右） | 0 |
| `row` | 索引の行（0以上の整数） | 文書内で読み込んだ順番 |

「索引順」は `indexPage` → `column` → `row` の順です。位置情報を省略した文書は、ファイル名順・配列順を保ちます。

## データの直し方

- `data/kitami/index-935.json` から `index-951.json` は、キタミ式の**索引ページ別**の用語です。`data/gokaku/index-786.json` などは合格教本のデータです。
- 各 `entries` の `word`（索引語）と `pages`（本文ページ）を直してください。確認できた項目は `needsReview` を `false` にできます。行の特定には `indexPage`、`column`（0=左、1=右）、`row` を使えます。
- GitHubへ送信すると、公開サイトの検索用データが自動生成されます。JSONに構造や型の誤りがある場合は公開を止め、Actionsのログにファイル名と項目位置を表示します。
- `要確認一覧.csv` は全ての文書の `needsReview: true` の項目をまとめた一覧です。文書ID・文書名・元ファイルで修正箇所を特定できます。[公開サイトの最新CSV](https://akanegit.github.io/ap-index-search-kitami-gokaku/要確認一覧.csv) も取得できます。元画像は含みません。
- OCRで `word` または `pages` が空文字になった項目は、検索対象から除外します。元JSONには残り、`needsReview: true` なら要確認一覧にも残ります。

## 読み取りの精度

キタミ式は索引 p.935〜951 の画像から自動で読み取りました。**すべての項目が未校正**で、`needsReview` が `false` でも正しさを保証しません。読めない文字、抜けた行、別の行に紐付いたページ、途中で切れた複数ページ表記があり得ます。「要確認」は機械的に見つけた疑わしい項目の印です。

合格教本は以前作成した検索データを引き継ぎ、画像を除きました。`verified-extra.json` は以前確認した項目のうち索引ページを特定できなかったものです。合格教本の画像読取候補も未校正です。

`index-data.js` と `要確認一覧.csv` は生成ファイルです。公開時の自動生成結果はサイトに配信し、リポジトリには書き戻しません。手元のダブルクリック版やCSVを更新する場合は、Python 3.10以降の環境で `python build.py` を実行してください。

## GitHub Pagesの更新

このフォルダがGitリポジトリのルートです。GitHub Pagesの **Settings → Pages → Source** は **GitHub Actions** を使用します。[公開ワークフロー](.github/workflows/pages.yml) が `main` への送信ごとに検証・生成・公開します。

ローカルで追加・編集したデータを公開するときは、次のようにGitHubへ送信します。公開だけなら手元のPython実行は不要です。

```sh
git status
git add data
git commit -m "Update document index"
git push
```

送信後、数分で公開サイトに反映されます。公開状況はリポジトリの **Actions** または **Settings → Pages** で確認できます。

開発時の検証は `python -m unittest discover -s tests -v` で実行できます。Chromeを使った画面の検証は `python tests/browser_smoke.py --browser <Chrome実行ファイル>` です。
